Important confirmed implementations:
- SubscriptionRepository records lifecycle timestamps for cancellation/expiration and supports past-due handling.
- ChangeSubscriptionStatus validates legal transitions, uses a subscription advisory lock, persists lifecycle events, and fires lifecycle hooks.
- SynchronizeSubscriptionEntitlement does not automatically restore explicitly revoked licenses.
- EnforcePastDueSubscriptions uses a 7-day grace period before moving past_due subscriptions to suspended.
- CreateLicense uses a subscription-specific advisory lock and rechecks state before creating a license.
- GatewayEventRepository now uses a 5-minute processing lease with updated_at as the ownership token; finalization is conditional on that token.
- ProcessPaymentEvent stale-worker failure handling was fixed so a worker that loses processing ownership does not emit a false gateway-event-failed action.
- ActivateLicense uses a license-specific advisory lock so concurrent activation requests cannot bypass the activation limit.
- DeactivateLicense uses an activation-specific advisory lock and is idempotent.
- PayPal product/plan provisioning uses resource-specific advisory locks and rechecks mappings before provider creation.
- CreateSubscriptionCheckout validates product/plan status and redirect URL origin and compensates a provider subscription if local persistence fails and no local winner exists.
- ProcessPaymentEvent constructor mismatch was fixed; current Plugin.php wiring uses four arguments and the fatal error was confirmed gone by the user.

Schema:

ProductAdmin — CURRENT UI MILESTONE:
The user wanted Edit Product removed from the sidebar because the Products list already has an Edit action.

Problem encountered:
1. Edit Product was registered as a normal submenu item, so it appeared in the sidebar.
2. Registering it with a null parent caused:
   strip_tags(): Passing null to parameter #1 ($string) is deprecated
   in wp-admin/admin-header.php line 41.
3. Removing the submenu after normal registration caused:
   Sorry, you are not allowed to access this page.
4. Registering it as a hidden top-level page and then removing the menu still caused the same admin-header strip_tags null deprecation.

Root cause resolution:
The stable solution is to keep Edit Product fully registered as a normal submenu page and hide only its sidebar link with admin CSS.

Current local ProductAdmin behavior, CONFIRMED BY USER:
- Products visible in sidebar.
- Add Product visible in sidebar.
- Edit Product hidden from sidebar.
- Edit Product remains directly accessible through the row Edit link.
- Previous deprecation is gone.
- Previous access error is gone.

Important:
The user's successful local ProductAdmin change may not yet exist on GitHub main because GitHub code files are read-only to the assistant. Treat the user's local result as CONFIRMED USER-TESTED, but inspect GitHub main before assuming it is committed.
